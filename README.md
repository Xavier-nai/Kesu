# Kesu

一个精简的 Android 壁纸管理工具，只有「桌面壁纸」「锁屏壁纸」两个入口。

原生 Android / Java，无第三方运行时依赖。最低 Android 13（API 33），目标适配小米澎湃 OS 1–4。

## 安装测试版

[下载 Kesu 0.1.0 测试 APK](downloads/Kesu-0.1.0-debug.apk?raw=true)

此安装包在本地通过编译、10 项单元测试、Android Lint 和 APK 签名验证。尚待小米手机真机验证主题授权与替换流程。

## 实现范围

- 桌面：选择图片、按屏幕比例裁剪、预览、设置桌面壁纸、读取当前桌面图片（系统允许时）、保存图片到相册。
- 锁屏：通过用户授权直接访问小米主题壁纸目录，预览、备份、替换、恢复、提取，再由用户重新应用主题。
- 不包含联网、账号、景深抠图、DOCK、自动轮换或其他光锥功能。

## 锁屏使用方式

1. 先在小米主题商店下载并应用要修改的主题。
2. 打开「锁屏壁纸」，选择「授权主题目录」，在系统选择器中授权 Android 或下方的目标目录。若普通定位无法使用，可尝试参考光锥的「兼容授权」定位方式；它仍须获得系统实际授予的持久读写权限。
3. 刷新列表，点击正在使用的主题。能读取 metadata 时显示主题名称和作者，否则显示文件名。
4. 点击「选择图片并替换」，从相册选图、拖动或双指缩放裁剪，确认后执行备份及替换。
5. 进入主题商店，重新应用同一个主题，再检查锁屏背景和原有布局、动画是否正常。
6. 恢复时点击「恢复原图」，然后同样重新应用主题。

```text
Android/data/com.android.thememanager/files/MIUI/theme/.data/content/lockscreen
```

只更换该目录直接包含的可识别图片，不修改主题脚本、布局或其他文件。不是所有主题都从这里读取背景；内置图片、视频及其他主题结构需要另行适配。

## 数据与写入保护

- 首次替换前，在同一目录保存「原壁纸 + 原文件名」备份，与参考 APK 的命名方式一致。后续更换不覆盖首次原图，恢复后也保留备份。
- 备份必须读回并逐字节一致，才会开始覆盖主题图片。每次写入同样读回校验；写入失败或内容不一致时尝试恢复到本次操作前的图片。
- 自动恢复失败会明确报告，原图备份继续保留。损坏或空的目标文件只要还有备份，仍可在列表中选择恢复。
- 空备份、无效图片、授权失效、目录不匹配或无法写入时停止操作。单文件上限 32 MiB。
- SAF 跨文件写入无法保证断电时的原子性。异常退出后如图片受损，重新授权并使用原图备份恢复；不要手动删除备份。
- 已选桌面图片保存在应用私有目录。提取和导出的图片保存在相册 `Pictures/Kesu`。
- 当前桌面图片仅尝试读取参考 APK 使用的小米静态图／视频缩略图路径；系统不允许读取时明确提示。应用不会申请更高权限，也不会把已选图片冒充为系统当前壁纸。
- 仅申请 `SET_WALLPAPER`，无联网、全盘访问、无障碍、Root 或 Shizuku 依赖。

## 构建

需要 JDK 17、Android SDK Platform 35、Build Tools 35.0.0。将 SDK 路径填入本机 `local.properties`，该文件不提交。

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Windows 使用 `gradlew.bat`。测试安装包输出为 `app/build/outputs/apk/debug/app-debug.apk`。

推送 main 后，GitHub Actions 自动执行单元测试、Lint 和 APK 构建。在运行记录的 Artifacts 中下载 `Kesu-debug`。CI 生成的是测试签名版本；不同运行环境的测试签名可能不同，正式持续升级需配置固定签名。

## 验证范围

单元测试覆盖首次备份、多次替换保留原图、备份失败、备份校验失败、目标写入失败、目标校验失败、回滚失败、空输入拦截及损坏目标恢复。

主题目录访问受 Android、澎湃系统和系统文件选择器限制。澎湃 OS 1–4 是适配目标，尚未逐版本真机验证；参考 APK 在用户设备上成功，不代表本应用已经完成真机验证。
